# Repeated delete confirmation modals from dropdown action re-initialization

**Date:** 2026-02-26 22:46
**Files:** resources/js/full-calendar.js
**Severity:** high

## Problem

Clicking the delete action in the event dropdown opened a confirmation modal.
After closing it and clicking delete again, multiple confirmation modals opened
(3, then 5-6, etc.), growing with each interaction.

## Root Cause

The dropdown injects ActionButton HTML dynamically and re-initializes Alpine behavior.
`Alpine.initTree(...)` was called on the dropdown content wrapper itself on every open.
That re-initialized the wrapper and its descendants repeatedly, causing duplicate
MoonShine/Alpine click handlers to accumulate and trigger multiple confirmation modals.

## Solution

Changed Alpine re-initialization to target only newly injected child nodes:
- Keep the wrapper node stable
- Run `Alpine.initTree(child)` for each child of the injected content container

This avoids re-initializing the wrapper and prevents event handler duplication.

## Prevention

- When using dynamic HTML injection (`x-html`), do not repeatedly call `Alpine.initTree`
  on a persistent wrapper node
- Re-initialize only new subtree roots inserted by the HTML update
- Add a regression check for repeated open/close/click cycles on delete confirmation
