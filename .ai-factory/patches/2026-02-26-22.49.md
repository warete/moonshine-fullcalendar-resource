# Reduce noisy timeGridDay layout-fix logs while keeping signal

**Date:** 2026-02-26 22:49
**Files:** resources/js/full-calendar.js
**Severity:** low

## Problem

The `timeGridDay` layout recovery logs emitted four `INFO` messages for every event load
(`raf-1`, `raf-2`, `timeout-50ms`, `timeout-250ms`), which made it harder to inspect
dropdown/action-related logs in the console.

## Root Cause

The layout-fix code intentionally runs multiple recovery phases, but all phases were logged
at the same `INFO` level even though only one high-signal message is usually needed.

## Solution

Keep the first phase (`raf-1`) at `INFO` and downgrade subsequent phases to `DEBUG`.
This preserves visibility that the fix is active while reducing console noise.

## Prevention

- For retry/recovery loops, log one high-signal `INFO` event and downgrade repeated attempts
  to `DEBUG`
- Keep noisy diagnostics behind `debug` mode unless they indicate distinct user-visible states
