# Increased FullCalendar event fill opacity to 50%

**Date:** 2026-02-27 10:51
**Files:** resources/css/full-calendar.css, public/css/full-calendar.css
**Severity:** low

## Problem

Event chips in the calendar still looked too transparent after the previous contrast pass.
The user wanted them visibly denser, with approximately 50% tonal fill instead of the
current 22-28% range.

## Root Cause

The earlier adjustment improved readability but kept the tonal background deliberately soft.
That left the event surfaces visually lighter than the desired design direction, especially
against neutral calendar cells.

## Solution

Raised the background tint of all event variants to 50%:

- default `--fc-event-bg-color`
- semantic event classes (`primary`, `secondary`, `error`, `warning`, `success`, `info`)
- custom accent events via `.msfc-event-custom-tonal`

Then rebuilt the published CSS asset so runtime output matches the source.

## Prevention

- When tuning visual density, update the default event token and all semantic overrides together
- Keep custom accent event styling in sync with standard event variants to avoid inconsistent chips
- Rebuild package assets immediately after CSS changes so manual QA reflects the real shipped styles
