# timeGridDay hidden events due to ambiguous date string formatting

**Date:** 2026-02-26 20:37
**Files:** src/Resources/FullCalendarResource.php, resources/js/full-calendar.js
**Severity:** high

## Problem

`timeGridDay` loaded events successfully (`count > 0`) but rendered no events on first load.
Other views worked. Logs indicated the frontend had events, but visibility in the day grid was inconsistent.

## Root Cause

The resource formatter returned string dates "as-is" when model attributes were strings.
If the DB values were not already ISO8601 with explicit timezone, FullCalendar parsed them ambiguously
(especially when calendar `timeZone` was set to `UTC`), which can move events outside the active day range.

## Solution

- Normalize string dates in `formatDateTime()` using `Carbon::parse(...)->format('c')`
- Keep a safe fallback (raw string) with warning logs if parsing fails
- Add client-side `[FIX][day-view]` diagnostics to log active range and parsed event sample in `timeGridDay`

## Prevention

- Always emit ISO8601 timestamps with timezone offsets from backend APIs used by FullCalendar
- Avoid returning raw DB datetime strings unless their format/timezone is guaranteed
- Add a regression case for `timeGridDay` with `timeZone: UTC` and string-backed datetime columns
