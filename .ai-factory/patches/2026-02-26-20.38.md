# timeGridDay recovery when parsed events exist but DOM is empty

**Date:** 2026-02-26 20:38
**Files:** resources/js/full-calendar.js
**Severity:** high

## Problem

In `timeGridDay`, events were fetched and parsed (`parsedCount > 0`) but no `.fc-timegrid-event`
elements appeared until the user manually switched views and returned to day view.

## Root Cause

This appears to be a FullCalendar rendering/slicing timing issue on initial `timeGridDay` mount
inside the current MoonShine/Alpine container lifecycle. Data and parsed events exist, but the
initial DOM render of the time-grid event nodes can fail intermittently.

## Solution

- Added a render probe for `timeGridDay` that compares parsed events vs actual time-grid DOM nodes
- If parsed events exist but `.fc-timegrid-event` count is zero, perform a one-time recovery:
  `calendar.changeView('timeGridDay', currentDate)` + `updateSize()`
- Added `[FIX][day-view]` logs for probes and recovery outcome

## Prevention

- Add a smoke test for initial `timeGridDay` render in the package demo/manual QA checklist
- Keep explicit logs for "fetched", "parsed", and "rendered DOM" counts to isolate data vs render bugs quickly
