# Incorrect API URL with [object Object] in path

**Date:** 2025-02-16 22:35
**Files:** src/Resources/FullCalendarResource.php
**Severity:** critical

## Problem

When the FullCalendar component loads, it makes an AJAX request to fetch events, but the URL is malformed:
```
/admin/resource/calendar-events-resource/[object%20Object]
```

The `[object Object]` indicates that an object was converted to a string instead of being properly serialized in the URL path.

## Root Cause

The `getEventsEndpoint()` method was using `$this->getRouter()->to('full-calendar.events.list')` to build the URL. However, when routes are registered with `Route::moonshine()` using `withResource: true`, MoonShine automatically scopes the routes under the resource URI key.

The router's `to()` method requires additional context for resource-scoped routes, but was being called without proper parameters, causing the resource object itself to be converted to a string and inserted into the URL.

## Solution

Modified `getEventsEndpoint()` to build the URL manually using the resource's URI key:

```php
public function getEventsEndpoint(): string
{
    $resourceUri = $this->getUriKey();
    $endpoint = '/' . trim(config('moonshine.route.prefix', 'admin'), '/')
                . 'resource/' . $resourceUri . '/full-calendar/events';

    return $endpoint;
}
```

This constructs the correct URL pattern: `/admin/resource/{resourceUri}/full-calendar/events`

## Prevention

1. **Test URL generation**: Always verify that URLs are correctly formed when using router helpers
2. **Understand route scoping**: When using `withResource: true`, routes are automatically scoped under the resource URI
3. **Add URL logging**: Include logging for URL generation to catch these issues early
4. **Check route definitions**: Match the URL building logic with how routes are actually defined
