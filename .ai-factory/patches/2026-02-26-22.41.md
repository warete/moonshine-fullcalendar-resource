# Calendar actions dropdown should track event while scrolling

**Date:** 2026-02-26 22:41
**Files:** resources/js/full-calendar.js, resources/views/components/full-calendar.blade.php
**Severity:** medium

## Problem

Using `position: fixed` solved z-index/viewport clipping issues, but the dropdown no longer
stayed visually attached to the clicked event when the page or calendar scroller moved.

## Root Cause

`position: fixed` anchors the overlay to the viewport, not to the calendar container.
Without tracking scroll/resize and recomputing coordinates from the original event element,
the dropdown drifts away from the clicked event after scrolling.

## Solution

- Switched dropdown back to `position: absolute` inside the calendar container
- Stored the clicked event DOM node as an anchor (`dropdownAnchorEl`)
- Added reposition listeners for:
  - `document:scroll` in capture mode (covers nested FullCalendar scrollers)
  - `window:resize`
- Recompute dropdown coordinates on every reposition event using viewport clamp + root-relative translation
- Close dropdown if the anchor element disappears from the DOM

## Prevention

- For overlays tied to moving elements, choose a strategy explicitly:
  - `fixed` + live tracking, or
  - `absolute` + root-relative recompute on scroll/resize
- If UI is rendered inside nested scroll containers (FullCalendar grids), listen to scroll with capture mode
- Keep a stable anchor reference and close the overlay when the anchor unmounts
