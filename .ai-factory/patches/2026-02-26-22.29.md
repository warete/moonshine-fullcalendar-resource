# Calendar event actions missing when resource overrides formatEvent

**Date:** 2026-02-26 22:29
**Files:** src/Resources/FullCalendarResource.php
**Severity:** medium

## Problem

Calendar events JSON did not include the new actions payload (`extendedProps.moonshineFullCalendar.actions`) for some resources.
The endpoint returned events without actions even after implementing backend action rendering.

## Root Cause

Actions payload injection was implemented inside the base `FullCalendarResource::formatEvent()` method.
Consumer resources can override `formatEvent()` (often to add fields like `backgroundColor` / `borderColor`) and may not call `parent::formatEvent()`.
When that happened, the new actions payload logic was bypassed entirely.

## Solution

Moved the guarantee point for action payload injection to `getCalendarItems()`:
- format the event (`formatEvent()`)
- then always run a post-processing step (`ensureCalendarEventActionsPayload(...)`)

This preserves custom `formatEvent()` output while injecting actions payload afterward.
If a resource already adds the actions payload itself, the post-processing step detects and preserves it.

## Prevention

- Do not rely on overridable formatting hooks as the only place for required transport metadata
- For package-level JSON contracts, add a final normalization/enrichment pass in the top-level collection builder (`getCalendarItems()`)
- When adding new payload keys, test against a resource that overrides `formatEvent()` and does not call `parent`
