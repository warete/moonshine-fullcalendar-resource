# Calendar actions dropdown remains open after clicking action button

**Date:** 2026-02-26 22:40
**Files:** resources/js/full-calendar.js, resources/views/components/full-calendar.blade.php
**Severity:** low

## Problem

When a user clicked an action button inside the event actions dropdown (for example,
opening the edit modal), the dropdown remained visible on top of the page instead of
closing.

## Root Cause

The dropdown had outside-click and escape dismissal, but no explicit close behavior for
clicks on interactive elements inside the dropdown. MoonShine async buttons handled the
click, but the dropdown state was never reset.

## Solution

- Added delegated click handling on the dropdown content wrapper
- Detect clicks on actionable elements (`a`, `button`, `.btn`, `[role="button"]`)
- Close the dropdown with a `setTimeout(0)` after the click is dispatched so it does not
  interfere with MoonShine/Alpine async action handlers and modal opening

## Prevention

- For interactive overlays, define close behavior for all exit paths:
  outside click, escape, refresh, and internal action activation
- Use delegated handlers on the overlay container when content is injected dynamically
- When integrating with third-party handlers (MoonShine async buttons), close on the next
  tick to avoid breaking event sequencing
