# Calendar actions dropdown clipped and positioned off-screen

**Date:** 2026-02-26 22:35
**Files:** resources/js/full-calendar.js, resources/views/components/full-calendar.blade.php
**Severity:** medium

## Problem

The event actions dropdown opened under FullCalendar markup (buttons were not clickable),
could render outside the viewport when positioned to the right of wide events, and had
unreliable dismissal behavior when clicking outside.

## Root Cause

The dropdown used container-relative absolute positioning with a low visual priority
(`z-30`) and a fixed "right side" placement strategy. In FullCalendar layouts this can
cause overlap/clipping by calendar layers and overflow issues on wide events.

Additionally, outside-close relied on a single JS listener path; adding an Alpine
`click.outside` fallback improves resilience.

## Solution

- Switched dropdown positioning to `position: fixed` with viewport-aware clamping
- Added dynamic placement (`top`/`bottom`) based on available viewport space
- Raised dropdown stacking order (`z-index: 10000`) and ensured pointer events are enabled
- Added extra outside-close handling (`document click` + Alpine `click.outside`)
- Reduced dropdown visual footprint (padding/gap/max width) and made width `max-content`
  so it adapts to the number of action buttons

## Prevention

- For overlays rendered over complex widgets (FullCalendar, tables, modals), prefer
  viewport-based positioning (`fixed`) and explicit z-index instead of relying on local
  stacking contexts
- Clamp overlay coordinates to the viewport and avoid one-sided placement assumptions
- Add both JS and Alpine outside-dismiss paths for interactive injected UI
