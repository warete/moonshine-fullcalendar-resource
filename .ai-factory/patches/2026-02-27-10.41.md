# Rebased FullCalendar theme on reference.css and remapped to MoonShine tokens

**Date:** 2026-02-27 10:41
**Files:** resources/css/full-calendar.css, public/css/full-calendar.css
**Severity:** medium

## Problem

The calendar theme had drifted into a custom visual direction that did not match the
reference design the user preferred. The current stylesheet was much heavier than the
approved reference and no longer felt aligned with MoonShine's token-based look.

## Root Cause

The previous pass was designed from scratch instead of inheriting the styling system
from `.stuff/reference.css`. That introduced a separate visual language (surfaces,
borders, shadows, spacing) rather than reusing the package's intended reference and
translating it into MoonShine runtime tokens.

## Solution

Replaced the calendar theme in `resources/css/full-calendar.css` with a plain-CSS
version based directly on `.stuff/reference.css`:

- preserved the reference hierarchy for buttons, events, popovers, and grid spacing
- remapped style values to MoonShine token fallbacks (`--color-*`, `--radius-*`, `--shadow-*`)
- kept package-specific styles for loading, error, custom event tones, and event actions dropdown
- rebuilt assets so `public/css/full-calendar.css` matches the updated source

## Prevention

- For future visual tweaks, start from the approved reference stylesheet before adding
  bespoke design adjustments
- Keep package CSS close to the reference structure, and only adapt token names plus
  package-specific selectors
- Run the asset build after stylesheet changes so the published CSS is not stale
