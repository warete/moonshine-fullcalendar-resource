# timeGridDay initial render shows no events until view toggle

**Date:** 2026-02-26 20:34
**Files:** resources/js/full-calendar.js, src/Resources/FullCalendarResource.php
**Severity:** high

## Problem

When the calendar starts in `timeGridDay`, the backend request returns events and the JS logs
`Events loaded successfully`, but events are not drawn. Switching to another view and back makes them appear.

The browser console also shows `Unknown option 'timezone'`.

## Root Cause

Two contributing issues:

1. `timeGridDay` is more sensitive to initial layout timing (container visibility / x-cloak / async rendering).
   The calendar could finish data loading before the layout fully settled, so events existed but were not positioned visibly
   until a manual view switch forced recalculation.

2. The package emitted legacy `timezone` config key instead of FullCalendar's `timeZone`, causing warnings and increasing
   configuration ambiguity.

## Solution

- Added a guarded layout refresh for `timeGridDay` (`updateSize()` + `render()`) after init and after events load
- Added verbose `[FIX][layout]` logging to confirm when the layout fix runs and with how many events
- Normalized frontend config by removing unsupported `timezone` before creating FullCalendar config
- Updated PHP config generation to emit `timeZone` instead of `timezone`

## Prevention

- For view-specific rendering bugs, distinguish "data loaded" from "layout rendered" with explicit logs
- Avoid passing legacy/unknown option keys to third-party widgets
- Add a smoke test/manual checklist for initial render in each supported view (`day`, `week`, `month`, `list`)
