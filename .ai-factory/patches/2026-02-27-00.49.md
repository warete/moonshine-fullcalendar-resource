# FullCalendar visual contrast tune for borders, events, and dropdown background

**Date:** 2026-02-27 00:49
**Files:** resources/css/full-calendar.css
**Severity:** medium

## Problem

After the FlyonUI-inspired redesign, the calendar looked too washed out in some MoonShine palettes:
- grid borders were too subtle in dark mode;
- event chips were too transparent;
- the event actions dropdown looked visually transparent because its background used a translucent mix + blur.

## Root Cause

The redesign used low-opacity tonal values optimized for a softer UI, but in dark palettes the combination of:
- weak border alpha (`--msfc-border-soft` at 9%),
- very soft event background alpha (14%), and
- translucent dropdown surface (`color-mix(..., transparent)` + blur)

reduced contrast too much and made key UI boundaries/surfaces hard to read.

## Solution

Adjusted CSS contrast levels while preserving token-based theming:
- increased border opacity tokens (`--msfc-border-soft`, `--msfc-border-strong`);
- used stronger borders for the outer scrollgrid and header/timegrid structural cells;
- increased event tonal fill opacity (default and custom colored events);
- switched event-actions dropdown to a solid MoonShine token background (`var(--color-base)`) and removed blur to restore a clear black/white theme surface.

## Prevention

- For visual redesign passes, validate both light and dark palettes before finalizing alpha-heavy tonal styles.
- Use separate tokens for `soft` and `strong` borders and apply stronger borders to structural grid edges.
- Avoid translucent popover/dropdown shells unless contrast is verified on dark themes.
- Add a visual QA checklist item for "surface opacity looks solid enough" in overlays/popovers.
