# FullCalendar week header separators visibility and dropdown token scope fallback

**Date:** 2026-02-27 00:56
**Files:** resources/css/full-calendar.css
**Severity:** medium

## Problem

In `timeGridWeek` dark theme, vertical separators between weekday header cells were still not visually visible. The event action dropdown also intermittently showed no rounding because radius styles depended on local theme variables.

## Root Cause

Two separate issues overlapped:

1. Header separators: simple border-color and inset lines on `th.fc-col-header-cell` can become visually lost due to table border-collapse/layering and close contrast against the header surface in dark mode.
2. Dropdown radius styles used `--msfc-*` variables defined on `.full-calendar.fc`; the dropdown is teleported/rendered outside that subtree, so those variables were unavailable at runtime and computed to fallback `0`/none values.

## Solution

- Added a dedicated stronger token `--msfc-border-header` for header separators.
- Drew separator lines using multiple layers (`border-color`, `outline`, pseudo-elements on `th`, and pseudo on `.fc-scrollgrid-sync-inner`) so at least one layer remains visible in collapsed table rendering.
- Kept dropdown styling on global MoonShine/base fallback tokens (`--radius-*`, `--color-base-stroke`, `--shadow-md`) instead of `--msfc-*`.

## Prevention

- For FullCalendar table-based headers, verify visual separators in both `dayGrid` and `timeGrid` after any border changes.
- When styling teleported dropdowns/popovers, avoid depending on CSS variables scoped to the calendar root unless they are re-declared on the dropdown container.
- Confirm published vendor assets are refreshed before judging runtime styling fixes.
