# FullCalendar timezone - 'local' вместо timezone приложения

**Date:** 2026-02-16 23:30
**Files:** resources/js/full-calendar.js
**Severity:** medium

## Problem

FullCalendar использовал `timeZone: 'local'` (timezone браузера пользователя) вместо timezone приложения (`config('app.timezone')`).

**Симптомы:**
- API возвращает `2026-02-16T11:23:00+00:00` (UTC)
- В календаре показывается `14:23` (если браузер в Moscow timezone)
- Ожидается: время в timezone приложения (независимо от браузера)

## Root Cause

В `resources/js/full-calendar.js` строка 124:
```javascript
timeZone: this.config.timeZone || 'local',
```

1. PHP передавал timezone как `timezone` (lowercase), а JavaScript искал `timeZone` (camelCase)
2. Если `timeZone` не найден, использовался fallback `'local'` = timezone браузера

## Solution

**1. Исправлен JavaScript** (`resources/js/full-calendar.js`):

```javascript
// [FIX] Support both timeZone and timezone (PHP convention)
timeZone: this.config.timeZone || this.config.timezone || 'local',
```

Теперь поддерживаются оба варианта:
- `timeZone` - JavaScript convention (camelCase)
- `timezone` - PHP convention (lowercase) - используется в `FullCalendarResource::getCalendarConfig()`

**2. Добавлено логирование** для отладки timezone:

```javascript
this.log('debug', '[FIX] Timezone configuration', {
    configTimeZone: this.config.timeZone,
    configTimezone: this.config.timezone,
    finalTimeZone: timeZone,
    'local': Intl.DateTimeFormat().resolvedOptions().timeZone
});
```

## Как это работает

1. PHP: `$this->timezone` берётся из `config('app.timezone')` (например, `Europe/Moscow`)
2. PHP: В `getCalendarConfig()` передаётся как `'timezone' => 'Europe/Moscow'`
3. JS: `this.config.timezone` теперь распознаётся и передаётся в FullCalendar
4. FullCalendar: Конвертирует UTC времена из API в указанную timezone для отображения

## Prevention

1. **Consistent naming** - использовать либо camelCase везде, либо явно поддерживать оба варианта
2. **Document timezone behavior** - добавить документацию о том, как работает timezone
3. **Test with different timezones** - тестировать с UTC, Europe/Moscow, America/New_York
4. **Add logs for configuration** - логировать все критичные конфигурационные параметры
