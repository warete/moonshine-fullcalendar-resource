# FullCalendar refresh ignored due to resource filter mismatch

**Date:** 2026-02-26 20:26
**Files:** resources/js/full-calendar.js, resources/views/components/full-calendar.blade.php
**Severity:** high

## Problem

MoonShine CRUD response returned a valid event:
`fullcalendar:refresh|resource~calendar-events-resource`
but the calendar component still did not refetch events.

## Root Cause

The JS listener filtered refresh events by `resource`, but the calendar's resource key
was derived by parsing the `endpoint` URL (`getResourceUriFromEndpoint()`).

This is fragile and depends on a specific route path shape. When the parsed value did not
match the resource key from the event payload, the component silently skipped refresh.

## Solution

- Pass the resource URI directly from Blade to Alpine props (`resourceUri`)
- Use `props.resourceUri` as the primary value for refresh event filtering
- Keep endpoint parsing only as fallback
- Add logging for the resource source (`props` vs `endpoint`) and fallback refresh when resource URI is unknown

## Prevention

- Do not infer critical identifiers (resource IDs/keys) by URL parsing when the server can provide them explicitly
- For custom event filters, log both sides of the comparison (`event` vs `component`) and the value source
- Add a small regression test/smoke check for "response event arrives + matching resource => refetchEvents() called"
