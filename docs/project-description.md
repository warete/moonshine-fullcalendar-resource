Project Description — MoonShine FullCalendar Package (MVP)

1. Общее описание

Разрабатывается Laravel-пакет для MoonShine v4, добавляющий компонент календаря на базе FullCalendar.js. Компонент размещается на странице index ресурса (аналогично TableBuilder), работает асинхронно и интегрирован с CRUD ресурса через стандартные механизмы MoonShine.

Пакет предоставляет:
•	Calendar UI-компонент
•	Интеграцию с ModelResource
•	Асинхронную загрузку событий
•	Открытие edit-формы в модальном окне MoonShine
•	Поддержку всех режимов отображения FullCalendar (month/week/day/list)

⸻

2. Цели MVP

Минимальная цель — получить переиспользуемый MoonShine-компонент календаря, который:
•	отображает события из ресурса
•	открывает edit-форму в модалке по клику
•	обновляется после создания события
•	не требует кастомных ACL или сложной бизнес-логики

⸻

3. Стек и технологические ограничения

Backend
•	PHP: ^8.2
•	Laravel: ^11
•	MoonShine: ^4
•	Eloquent model resource (без кастомных Page-классов)
•	Custom index page ресурса с компонентом календаря

Frontend
•	Vite
•	FullCalendar через npm
•	Alpine.js компонент (встроенный в MoonShine)
•	Tailwind 4 (дизайн MoonShine)
•	Кастомная тема FullCalendar на токенах MoonShine — не входит в MVP

⸻

4. Архитектурная модель компонента

Компонент календаря реализуется как переиспользуемый MoonShine UI-компонент, который:
•	рендерится в Blade
•	инициализирует Alpine.js состояние
•	внутри Alpine инициализирует FullCalendar
•	общается с backend через MoonShine.request

Компонент не является Field. Он используется только на index-странице ресурса.

⸻

5. Доменные данные (Event Model)

Модель событий содержит поля:
•	title — строка, обязательная
•	start — datetime с таймзоной, обязательный
•	end — datetime с таймзоной, обязательный
•	color — строка, nullable
•	description — текст, nullable

События не привязаны к пользователю, организации или другим сущностям.

Таймзона — таймзона приложения (config('app.timezone')).

⸻

6. Поведение UI

Отображение

Календарь отображается на странице index ресурса и заменяет/дополняет таблицу.

Поддерживаются все режимы FullCalendar:
•	month
•	week
•	day
•	list

Загрузка событий

При изменении диапазона видимости календаря выполняется асинхронный запрос к backend для получения событий в диапазоне дат.

Редактирование

При клике на событие:
1.	Alpine-компонент получает edit URL
2.	Выполняет MoonShine.request(ctx, editUrl, 'get')
3.	MoonShine обрабатывает ответ и автоматически открывает edit modal, так как в ресурсе включён editInModal

Создание

Создание событий выполняется стандартной кнопкой MoonShine “Create”.
После успешного создания календарь выполняет refetch списка событий.

⸻

7. Роутинг и взаимодействие с ресурсом

Стандартные маршруты ресурса

Используются встроенные маршруты MoonShine:
•	create
•	update
•	delete

Кастомные маршруты (resource-scoped)

Добавляются маршруты, привязанные к ресурсу:
1.	Получение списка событий по диапазону дат
2.	Обновление дат события при drag/drop/resize (endpoint закладывается в MVP, UI можно включить позже)

Маршруты должны регистрироваться через механизм MoonShine resource routing с сохранением контекста ресурса и middleware.

⸻

8. Контракт API

Получение событий

Вход:
•	start (ISO8601)
•	end (ISO8601)

Выход:
•	id
•	title
•	start
•	end
•	color
•	description

Обновление дат события (заготовка)

Вход:
•	id
•	start
•	end

Выход:
•	success
•	обновлённые данные события (опционально)

⸻

9. Форматирование и таймзоны

События хранятся в БД как datetime с таймзоной.
Необходимо предусмотреть в классе ресурса расширяемый хук для:
•	нормализации дат при сохранении
•	форматирования дат при выдаче в календарь

Хук должен быть переопределяемым без изменения пакета.

⸻

10. JS архитектура компонента

Компонент реализуется как Alpine.js data-component со следующими обязанностями:
•	инициализация FullCalendar
•	загрузка событий через асинхронный запрос
•	обработка клика по событию
•	рефетч после CRUD-операций
•	(в будущем) обработка drag/drop/resize

Все HTTP-запросы выполняются через глобальный helper MoonShine MoonShine.request.

⸻

11. Ограничения MVP

В первую версию не входят:
•	кастомная Tailwind-тема FullCalendar
•	права доступа и ownership событий
•	повторяющиеся события
•	проверки конфликтов пересечений
•	фильтрация и категории
•	UI drag & drop (endpoint закладывается, но интерфейс можно включить позже)

⸻

12. Расширяемость

Пакет должен предусматривать точки расширения:
•	переопределение форматирования дат
•	кастомизация источника событий
•	возможность добавления фильтров и цветовых правил
•	включение drag/drop/resize без изменения архитектуры

⸻

13. Ожидаемый результат MVP

После установки пакета разработчик должен иметь возможность:
1.	Создать EventResource
2.	Подключить Calendar component на index странице ресурса
3.	Получить рабочий календарь с событиями
4.	Открывать edit форму события в модальном окне
5.	Создавать события через стандартный CRUD и автоматически видеть их в календаре

⸻
